Fleet Connector
Reference Implementation

Ship the ngrok agent under your brand and your signature.

Fleet Connector turns golang.ngrok.com/ngrok/v2 into a service you own end to end. You control the binary name, the code-signing certificate, the installer, and the update channel. Configure each deployment the way it needs: a scripted silent install, an interactive setup wizard, or a config file you manage by hand. Then push a new signed build the moment you trigger one.

1. Fork the repo

This is a reference implementation meant to be renamed and re-signed as your own, not installed as-is.

Fork the repo before doing anything else. Your service name, wordmark, and signing certificate will live in a copy you control, not in this one.

2. Build your release

A one-time step on your own build machine. It doesn't run on every install. The output is a signed installer you distribute.

Clone your fork, then build the package for your target platform.

Windows
fleetconnect.exe · MSI (WiX v5)
1. Build
PowerShell · build
git clone https://github.com/<your-org>/fleet-connector.git
cd fleet-connector
go build -o fleetconnect.exe .\cmd\fleetconnect

dotnet tool install --global wix --version "5.*"
wix extension add WixToolset.Util.wixext/5.0.2
wix build installer\product.wxs `
  -ext WixToolset.Util.wixext/5.0.2 -arch x64 `
  -d FleetConnectExeSource=fleetconnect.exe `
  -out FleetConnector.msi
2. Sign
PowerShell · sign
# one-time: real CA-issued cert for production, self-signed for testing
$cert = New-SelfSignedCertificate -Type CodeSigningCert `
  -CertStoreLocation Cert:\CurrentUser\My -Subject "CN=Your Company"

Set-AuthenticodeSignature -FilePath FleetConnector.msi `
  -Certificate $cert -HashAlgorithm SHA256

# thumbprint to pin in Configure, step 4
(Get-AuthenticodeSignature FleetConnector.msi).SignerCertificate.Thumbprint
Linux
fleetconnect · systemd · .deb / .rpm
shell
git clone https://github.com/<your-org>/fleet-connector.git
cd fleet-connector
GOOS=linux GOARCH=amd64 go build -o fleetconnect ./cmd/fleetconnect

go install github.com/goreleaser/nfpm/v2/cmd/nfpm@latest
nfpm package --config installer/linux/nfpm.yaml \
  --packager deb --target dist/

3. Install

What actually reaches a target machine: the installer from the step above.

PowerShell (Administrator)
msiexec /i FleetConnector.msi /quiet
terminal
sudo dpkg -i fleetconnect_*.deb

4. Configure

Three ways to reach the same config.yaml, chosen by who's doing the install and when.

gen-config

Pre-stage config.yaml before the service ever starts. Scripted and silent, built for an RMM pushing to a fleet of machines at once.

Setup wizard

No config.yaml at first start? The service opens a local-only (127.0.0.1) web form, walks a person through it once, then shuts itself down the moment a valid config is written.

Hand-edit

Already deployed and need to change something? Edit config.yaml directly, or run fleetconnect edit-config to do it in $EDITOR with validation before it saves.

gen-config example, pre-staging a full first-boot config including remote updates:

gen-config
./fleetconnect gen-config \
  --description "store-042" \
  --upstream localhost:8080 \
  --authtoken "<your authtoken>" \
  --update-source-url "https://updates.example.com/latest/fleetconnect.msi" \
  --update-signer-thumbprint "AABBCCDDEEFF00112233445566778899AABBCCDD"
▸ gen-config flags full reference 
--description              human-readable description (required)
--upstream                 single-endpoint shorthand, e.g. localhost:8080
--authtoken                literal value, "env:VAR", or "file:PATH";
                            omit to mint a fresh credential via the API
--connect-url               custom/dedicated ngrok connect endpoint
--connect-ca-cert-file       PEM CA bundle to trust for --connect-url
--proxy-url                 outbound HTTP/SOCKS proxy for the agent's own connection
--heartbeat-interval         connection heartbeat interval, e.g. 30s
--heartbeat-tolerance         how long a missed heartbeat is tolerated, e.g. 1m
--update-source-url          Windows only; blank disables self-update
--update-signer-thumbprint    required whenever --update-source-url is set
--endpoint                   repeatable, for multi-endpoint installs

What it writes:

config.yaml
schema_version: 1
description: store-042
credential:
    provider: static
    params:
        authtoken: <your authtoken>
endpoints:
    - upstream:
        url: localhost:8080
update_source_url: https://updates.example.com/latest/fleetconnect.msi
update_signer_thumbprint: AABBCCDDEEFF00112233445566778899AABBCCDD
▸ config.yaml reference full schema 
schema_version               required, must be 1
description                  human-readable label (optional)
metadata                     opaque, dashboard/API-visible session metadata (optional)
credential:
  provider                    required — "static" is the only built-in provider
  params:                      map of strings — open-ended, but static only reads one key
    authtoken                    the only key the static provider reads
endpoints:                   list, one entry per tunnel (optional)
  - name                        friendly name (optional)
    url                         endpoint URL; blank = https, or tcp://, tls://
    upstream:
      url                         required — local address to forward to
      protocol                    "http1" (default) or "http2"
      proxy_protocol              "1", "2", or empty
      tls_verify                  verify the upstream's TLS cert (default: false)
      tls_verify_cas              PEM CA bundle path; empty = system CA pool
    bindings                    e.g. ["public"] or ["internal"] (optional)
    metadata                    opaque per-endpoint metadata (optional)
    description                 per-endpoint description (optional)
    traffic_policy              inline traffic policy, YAML or JSON string (optional)
    agent_tls_termination:      (optional)
      server_certificate          PEM certificate
      server_private_key          PEM private key
      mutual_tls_certificate_authorities   PEM CA bundle (optional)
    pooling_enabled              bool (optional)
connect_url                  custom/dedicated ngrok connect endpoint (optional)
connect_ca_cert_file         PEM CA bundle to trust for connect_url (optional)
proxy_url                    outbound HTTP/SOCKS proxy for the agent's own connection (optional)
heartbeat_interval            e.g. "30s" (optional)
heartbeat_tolerance            e.g. "1m" (optional)
log_level                    debug, info (default), warn, or error
update_source_url            Windows only; blank disables self-update
update_signer_thumbprint     required whenever update_source_url is set

Remote updates

  • update_source_url: where the agent downloads a new signed installer from.
  • update_signer_thumbprint: the certificate that must have signed it.

Set both (Configure, step 4) to turn it on. When ngrok's dashboard or API sends an update trigger over the agent's existing tunnel session, it downloads the installer and checks its signature against the pinned thumbprint.
